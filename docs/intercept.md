# 실행 중 수정 지시 (인터셉트)

작업이 진행되는 동안 입력창에 추가 지시를 보내면, **진행 중인 작업을 멈추거나 새로 시작하지 않고** 지금 작업에 이어서 전달합니다. Claude Code에서 실행 중에 메시지를 끼워 넣는 것과 같은 방식입니다. 원래 목표와 이미 끝난 결과, 모델 설정, 담당 범위는 그대로 둡니다. 새 지시와 원래 지시가 부딪치면 새 지시를 우선합니다.

## 끼어들기와 예약 (2026-10-10)

작업이 진행 중일 때 입력창 위 안내 줄 오른쪽에서 보내는 방식을 고릅니다. 선택은 이 브라우저·앱에 저장됩니다.

| 방식 | 뜻 | 보내면 |
|---|---|---|
| **끼어들기** (기본) | 지금 작업에 수정 지시 — Claude Code 에서 실행 중에 메시지를 끼워 넣는 것과 같음 | 아래 "쓰는 법" 그대로. 새 요청을 만들지 않음 |
| **예약** | 지금 작업이 끝난 뒤 시작할 **새 요청** | 작업 카드가 "예약됨 · 앞 요청이 끝나면 시작해요"로 생기고, 지금 작업은 건드리지 않음. 여러 개 예약하면 순서대로. 분배·모델 설정은 보낼 때 고른 값 |

- **Ctrl+Enter**는 이번 한 번만 반대 방식으로 보냅니다(끼어들기 모드에서 예약, 예약 모드에서 끼어들기).
- 예약한 요청은 앞 작업이 **중지·실패로 끝나도** 시작합니다. 허브가 재시작돼 앞 작업이 "중단됨"이 돼도 부팅 뒤 시작합니다. "지금 바꾸기"로 이어 하는 작업이 있으면 그 작업이 끝난 뒤에 시작합니다.
- 예약은 카드의 **예약 취소**로 지웁니다. 취소한 예약 뒤의 예약은 건너뛰고 이어집니다.
- 작업을 마무리하는 중(보고서 쓰기 등)이라 끼어들 수 없을 때는 자동으로 예약됩니다. `/goal`(목표)은 예약할 수 없습니다 — 끝난 뒤 보내세요.
- 서버: `POST /api/jobs { …, reserve: true }` → 작업 `reserved:true`, `after:<앞 작업 id>`, `status:'queued'`. 시작은 `jobs.startReserved(sessionId)`(앞 작업 `finish`·예약 취소·`resumeAfterRestart` 가 부름). `/api/status` 의 `capabilities.reserve`. 시험 `tests/reserve.test.mjs`

> **먼저 알아 둘 것**
> - 이 기능은 **허브 서버를 다시 시작해야 켜집니다**(아래 "적용하기"). 서버를 다시 시작하기 전에는 입력창에 "이 허브는 아직 실행 중 수정 지시를 지원하지 않아요"가 뜨고, 아무것도 보내지 않습니다.
> - "현재 작업에 전달됨"은 **AI가 지시를 받았다**는 뜻입니다. 지시대로 결과가 바뀌었는지는 작업 기록과 결과에서 직접 확인하세요.
> - Claude 작업에서 지시가 무시된 채 "완료"로 끝나는 경우가 확인되었습니다(아래 "알려진 제약"). 수정 지시를 보낸 Claude 작업은 결과 파일을 꼭 확인하세요.

## 쓰는 법

1. 작업이 진행 중인 대화를 엽니다. 입력창 위에 **수정 지시 모드** 안내 줄이 뜹니다. 지시를 받을 대화 제목, 지금 단계(계획 세우는 중 · 작업 실행 중 · 보고서 쓰는 중 · 목표 달성 판정 중), 실행 중 작업 수, 대기 작업 수가 나옵니다.
2. 입력창에 바꾸고 싶은 내용을 씁니다. 보내기 버튼이 보라색 **수정 지시 보내기**로 바뀝니다.
3. **Enter**로 보냅니다. 줄을 바꾸려면 Shift+Enter를 누릅니다. 한글을 조합하는 중에 누른 Enter로는 보내지지 않습니다.
4. 작업 카드 아래에 `수정 지시 #1`이 생기고 상태가 바뀌어 갑니다. **대상 N곳 보기**를 누르면 작업마다 어떻게 전달됐는지 볼 수 있습니다.

- 지시는 그 대화의 **진행 중인 작업 전체**에 갑니다. 지금 실행 중인 작업과 아직 시작하지 않은 작업 모두에 가고, 계획·보고서·목표 판정 담당도 받습니다. 특정 작업 하나만 고를 수는 없습니다. 지시 안에 "Codex 작업은 그대로 두고 …"처럼 적으세요.
- 이미 끝난 작업은 다시 실행하지 않습니다. 보고서를 쓰는 중에 구현을 바꾸는 지시를 보내면, 같은 작업 안에 필요한 **보완 작업**만 추가한 뒤 보고서를 새로 씁니다.
- 연달아 여러 번 보내도 됩니다. 보낸 순서대로(#1 → #2) 전달됩니다.
- 이미지도 함께 보낼 수 있습니다(최대 4장). 이미지만 보내도 됩니다.
- 수정 지시 모드에서는 `/goal`, `/review`, `@reviewer` 같은 입력도 **그냥 글**로 전달합니다. 새 목표나 새 요청을 만들지 않습니다.
- 분배 방식·모델 버튼은 흐리게 표시됩니다. 수정 지시는 지금 작업의 설정을 그대로 씁니다.

### 중지는 따로

- 입력창이 비어 있으면 보내기 자리에 **중지(■)** 버튼이 있습니다.
- 글을 쓰는 중에는 보내기 버튼 옆의 작은 **■** 버튼, 작업 카드의 **중지**, 세션 메뉴의 중지를 쓰세요. 중지해도 쓰던 글은 입력창에 남습니다.
- 목표(`/goal`) 판정 중에 누르는 중지는 **목표 중지**입니다.
- 중지는 "그만"이라는 뜻이고, 수정 지시는 "이렇게 바꿔서 계속"이라는 뜻입니다. 수정 지시를 보낸다고 작업이 취소되거나 처음부터 다시 실행되지 않습니다. 이미 고친 파일을 되돌리지도 않습니다.

## 상태 표시의 뜻

카드 머리에 붙는 상태:

| 표시 | 뜻 |
|---|---|
| 접수 중… | 브라우저가 허브로 보내는 중입니다. 이 동안 다시 누르거나 Enter를 눌러도 한 번만 보냅니다. |
| 수정 지시 접수됨 / 전달 대기 | 허브가 지시를 저장했습니다. 아직 AI에게 전달되지는 않았습니다. |
| 시작할 작업에 반영 예정 | 받을 작업이 아직 시작 전입니다. 그 작업이 시작할 때 지시를 넣습니다. |
| 현재 작업에 전달 중 | 실행 중인 AI에게 보내고 있습니다. |
| **현재 작업에 전달됨** | 실행 중인 AI가 **받았다고 확인**했습니다. 결과에 반영됐다는 뜻은 아닙니다. |
| 일부 작업에 전달하지 못함 | 받은 작업과 못 받은 작업이 섞여 있습니다. 대상 목록에 사유가 나옵니다. |
| 수정 지시 전달 실패 | 한 곳도 받지 못했습니다. 원문은 기록에 남습니다. |
| 중지로 전달 취소됨 | 작업을 중지해 전달 전의 지시를 취소했습니다. |
| 일부 전달 후 중지됨 | 이미 받은 작업의 기록은 유지하고, 시작 전 작업 등 아직 전달하지 않은 몫만 취소했습니다. |

대상 목록에 나오는 전달 방식:

| 표시 | 실제 동작 |
|---|---|
| 실행 중인 턴에 지시 추가 | **Codex**: 진행 중인 턴에 지시를 더합니다(`turn/steer`). 하던 명령은 멈추지 않고, 끝나는 대로 새 지시를 반영합니다. |
| 현재 턴을 멈추고 이어서 지시 | **Claude**: 현재 턴에 중단을 요청한 뒤(`interrupt`), 같은 연결·같은 세션에 새 메시지를 보냅니다. 이미 백그라운드로 돌린 명령은 계속될 수 있습니다. |
| 시작 프롬프트에 포함 | 아직 시작하지 않은 작업, 또는 계획·보고서 단계가 시작할 때 프롬프트에 넣습니다. |
| 같은 CLI 세션을 재개해 지시 | 위 두 방식을 쓸 수 없을 때의 대안입니다. 그 작업의 CLI만 끝낸 뒤 같은 세션을 `--resume` / `exec resume`으로 이어 갑니다. |

## 보내지 못했을 때

- 실패하면 입력과 첨부가 **그대로 남고**, 입력창 위에 사유가 나옵니다. 같은 내용을 다시 보내면 같은 요청으로 처리되어 두 번 들어가지 않습니다.
- 응답을 받기 전에 새로고침하면, 허브에 접수됐는지 확인합니다. 접수되지 않았으면 원문을 입력창에 되돌려 줍니다.
- 진행 중인 대화를 오가면 쓰던 글은 **대화별로 따로 보관**됩니다. 다른 대화에서 쓰던 글이 실행 중인 작업에 잘못 들어가지 않습니다.
- 작업이 막 끝나서 지시를 받지 못하면 "작업이 이미 끝나서…"가 뜹니다. 입력창은 새 요청 모드로 돌아가므로, **그대로 보내면 새 요청**이 됩니다.
- 허브가 다시 시작된 뒤에는 실행 중이던 작업이 "중단됨"이 되어 수정 지시를 받을 수 없습니다. 이때 되돌려진 글도 그대로 보내면 새 요청이 됩니다. 이어서 하려면 작업 카드의 **다시**를 쓰세요.
- 전달을 기다리는 지시가 20개 쌓이면 더 받지 않습니다. 앞의 지시가 전달된 뒤 다시 보내세요.

## CLI별로 확인된 것과 제약

2026-10-03 확인 기준: Claude Code 2.1.285, Codex CLI 0.160.0(허브가 고르는 Codex 앱 CLI)

| | Codex | Claude Code |
|---|---|---|
| 기본 전달 방식 | 실행 중인 턴에 추가(steer) | 현재 턴 중단 후 같은 세션에 새 메시지 |
| 최종 실제 CLI 시험 (t5, 1회) | 같은 thread를 유지하며 ALPHA 대신 BRAVO 파일 생성 ✅ | 같은 세션을 유지하며 ALPHA 대신 BRAVO 파일 생성, 백그라운드 완료 이후 결과 채택 ✅ |
| 하던 명령 | 보통 현재 도구 응답 이후 새 지시 확인 | 턴 중단 요청. 이미 백그라운드인 명령은 계속될 수 있음 |
| 시험 CLI로 확인한 것 | 연속 지시 순서, 병렬·대기 작업, 새로고침, 대화 전환, 중지, 보고 단계 보완 작업 | 같음 |

**알려진 제약**
- t4에서 발견한 Claude 조기 완료 결함은 수정했습니다. 백그라운드 작업이 남은 중간 결과는 보류하고, 작업 완료 알림 이후의 최종 결과를 기다립니다. 원래 실행 제한 시간을 넘기거나 CLI 연결이 끊기면 실패로 기록합니다. 감시용 상시 작업(`ambient`)은 완료 대기에서 제외합니다. 이 수정은 일반 Claude 작업에도 적용됩니다. 실제 시험에서 중간 대기 응답 뒤 BRAVO 파일 생성까지 확인했습니다.
- Codex는 하던 명령이 끝나야 새 지시를 반영합니다. 오래 걸리는 명령 중이면 반영도 그만큼 늦어집니다.
- Claude 중단 요청으로 전면 도구 실행이 멈출 수 있고, 백그라운드 명령은 계속될 수 있습니다. 이미 수행한 파일 변경과 외부 동작은 자동으로 되돌리지 않습니다.
- "같은 CLI 세션을 재개해 지시"(대안 경로), 이미지가 붙은 지시를 실제 모델이 처리하는 동작, 목표 판정 중 실제 CLI 전달은 아직 **실제 CLI로 확인하지 않았습니다.**
- 실제 Windows 한글 입력기, 휴대폰·Safari·Firefox, 원격 접속 화면에서는 아직 확인하지 않았습니다.

## 적용하기 (서버 재시작 필요)

- 화면 파일(`public/`)은 이미 새 버전이 나가고 있습니다. 서버(`server.mjs`, `lib/`)는 **다시 시작해야** 바뀝니다. 2026-10-03 확인 시 운영 허브는 아직 옛 서버였습니다(`/api/status`에 `capabilities` 없음).
- 적용 순서:
  1. 허브 폴더(`F:\01_프로젝트\90_개발\ai-hub`)에서 `npm run restart`를 실행합니다. 진행 중인 작업과 목표가 모두 끝날 때까지 기다렸다가 허브만 다시 시작합니다. **지금 이 기능을 만드는 작업도 진행 중인 작업이므로**, 이 작업이 끝난 뒤에 실행됩니다.
  2. 열려 있던 대시보드 탭을 새로고침합니다.
  3. 아무 작업이나 실행하고 입력창에 글을 써서, 보내기 버튼이 **수정 지시 보내기**로 바뀌는지 봅니다. "지원하지 않아요"가 그대로면 아직 옛 서버입니다.
