# 다른 AI 의견 (작업 도중 다른 쪽 AI에게 묻기)

2026-10-12 추가. 작업을 맡은 AI가 일하는 도중에 **다른 쪽 AI**(Claude ↔ Codex)에게 의견을 받습니다. 의견을 주는 쪽은 프로젝트 폴더를 **읽기만** 하고 파일을 고치지 않습니다. Paseo 의 advisor(두 번째 의견)·committee(서로 다른 AI가 따로 분석 → 종합 → 다시 검토) 방식을 참고했고, 코드는 새로 썼습니다.

## 고르는 법

입력창 아래 분배 버튼 메뉴의 **다른 AI 의견**. 고른 값은 이 브라우저·앱에 남고, 요청마다 `settings.consult`로 보냅니다.

| 방식 | `settings.consult` | 뜻 |
|---|---|---|
| **안 받기** (기본) | `off` | 맡은 AI가 혼자 판단. 도구를 붙이지 않음 |
| **필요할 때만** | `ask` | 막히거나 위험한 결정 앞에서 맡은 AI가 스스로 판단해 물음(작업 하나에 3번까지) |
| **꼭 받기** | `committee` | 고치기 전에 같은 문제를 따로 분석받고, 끝내기 전에 바뀐 내용을 검토받음(4번까지). 작업이 쉬워 보여도 건너뛰지 않게 지시 |

- 질문에 바로 답하는 요청, 옮겨 온 기록에는 붙지 않습니다.
- "꼭 받기"인데 의견을 한 번도 받지 못하고 끝나면 작업 카드 알림에 그 사실이 남습니다.
- 작업 카드 끝에 `Codex → Claude 의견 · 질문 · 10초` 줄이 생기고 **답 보기**로 답 전체를 펼칩니다.

## 동작

```
작업자 CLI ──(MCP 도구 ask_other_ai)──> scripts/oddin-ask-mcp.mjs ──POST /api/consult──> 허브 lib/consult.mjs
                                                              <──POST /api/consult/wait(길게 기다림)──   │
                                                                                     다른 쪽 CLI 를 읽기 전용으로 한 번 실행
```

1. 요청에서 켰으면 허브가 작업자(작업 단계만)에게 도구 서버 `oddin-ask`를 붙입니다 — Claude 는 `--mcp-config` 파일(브라우저 도구와 한 파일), Codex 는 `-c mcp_servers.oddin_ask.*`. 지시문 규칙은 `planner.consultRule`.
2. 작업자가 `ask_other_ai { question, context?, review? }`를 부르면 허브가 다른 쪽 AI를 `readOnly`로 같은 폴더에서 실행합니다. 지시문은 `buildConsultPrompt`: 사용자 요청 원문 · 맡은 일 · 질문 · 참고 · (검토면) 바뀐 파일.
3. `review: true`면 허브가 **이 작업을 시작한 뒤 지금까지 바뀐 것**을 뽑아 함께 넘깁니다(`Checkpoints.live` — 시작 스냅샷 ↔ 지금 폴더, 256KB 넘으면 파일 목록만). 스냅샷이 없으면 "직접 읽어 검토"로 넘깁니다.
4. 같은 작업의 다음 질문은 의견을 준 대화를 이어 씁니다(앞서 읽은 파일·판단을 기억). 이어 쓰기가 안 되면 새 대화로 한 번 더.
5. 답은 `runs/<작업>/<하위작업>/consult-<n>/result.md`, 지시문은 같은 폴더 `prompt.md`, 비교 내용은 `changes.diff`. 작업 기록에는 `kind:'consult'` 두 줄(물음·도착)만 남깁니다.

모델은 허브 내부 단계와 같은 규칙입니다(`router.internalSettings`): 자동이면 그 AI의 기본 모델·high, 사용자가 고정했으면 그 값.

## 지킨 것

- **서로 기다리다 멈추지 않게**: 부른 쪽이 실행 자리를 쥔 채 기다리므로 의견 요청은 전체 CLI 한도(`maxParallel`) 밖의 따로 둔 자리(`consult.parallel`, 기본 2)에서 돕니다.
- **기다리는 시간**: 도구 한 번을 기다려 주는 시간이 CLI 마다 짧아(Codex 기본 60초) `oddin-ask`에는 10분을 줍니다(Claude 서버별 `timeout`, Codex `tool_timeout_sec`). 도구 스크립트는 허브에 50초씩 나눠 물으며 9분까지 기다리고, 그보다 늦으면 요청 번호를 돌려줘 `ask_result { id }`로 이어 받게 합니다. 같은 질문이 다시 오면 돌고 있는 요청에 붙습니다(두 번 돌지 않음).
- **한도**: 작업마다 횟수 제한, 상대 AI 한도를 `consult.blockAt`(기본 90)% 이상 썼으면 받지 않음. 받지 않는 사정(꺼짐·횟수·한도·상대 AI 없음)은 오류가 아니라 "혼자 판단해 진행하고 결과에 적으라"는 글로 돌려줍니다.
- **끊기**: 작업을 중지하거나 하위 작업이 끝나면 남은 의견 요청을 끕니다. "지금 바꾸기"(재시작)도 끄고, 다시 켜면 돌던 요청은 끊긴 것으로 남습니다.
- **이 PC에서만**: `/api/consult`·`/api/consult/wait`는 원격에서 부를 수 없습니다(작업자 도구 전용). 답 보기 `GET /api/jobs/:id/consults/:task/:cid`는 다른 PC 세션이면 그 PC로 넘어갑니다.

## 설정 (`config.json` 의 `consult`, 모두 선택)

| 값 | 기본 | 뜻 |
|---|---|---|
| `enabled` | `true` | `false`면 요청에서 골라도 붙이지 않음 |
| `default` | `"off"` | 요청이 방식을 보내지 않을 때(화면은 늘 보냄) |
| `maxPerTask` / `committeeMax` | 3 / 4 | 작업 하나에서 물을 수 있는 횟수(필요할 때만 / 꼭 받기, 꼭 받기는 2 아래로 내려가지 않음) |
| `timeoutMinutes` | 8 | 의견 한 번의 제한 시간 |
| `waitSeconds` | 540 | 도구가 답을 붙잡고 기다리는 시간 |
| `blockAt` | 90 | 상대 AI 한도 사용률이 이 이상이면 받지 않음 |
| `parallel` | 2 | 동시에 도는 의견 요청 수 |

## 하지 않은 것

- **일 맡기기**(다른 AI가 파일을 고침): 같은 폴더 쓰기는 한 번에 하나, 되돌리기 기록은 요청 단위, 작업 목록은 계획 때 정해지는 구조라 따로 계획이 필요합니다. 지금은 플래너가 처음에 나눕니다.
- 예전 방식 실행기(`transport: legacy`)의 Codex 에는 도구가 붙지 않습니다(브라우저 도구와 같음).
