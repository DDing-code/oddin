# 전체 점검 (2026-10-12)

사용자 "오딘 전체 점검해서 개선할 점 있을까?" → "전부 해줘". 직접 잰 수치(디스크·작업 자료·부하)와 세 갈래 검토(접근 통제·작업 엔진·화면)에서 나온 것, 그리고 고친 내용이다.

## 급한 것 — 실제로 일어난 흔적이 있던 것

| 무엇 | 원인 | 고침 |
|---|---|---|
| Codex 대화를 이어 쓸 때 허브가 수십 초 멈춤 | `thread/resume` 응답 한 줄에 지난 대화 전체(그림 원본 포함, 실측 최대 102MB)가 오는데 조각마다 처음부터 줄바꿈을 다시 찾고(크기의 제곱), 통째로 해석해 다시 직렬화해 기록했다 | `util.lineSplitter`(100MB 한 줄 0.04초), 큰 응답은 스레드 id 만 꺼냄(`native-workers.bigResponse`), 큰 줄·`turn/diff/updated` 는 기록하지 않음 |
| "지금 바꾸기"가 두 번 불리면 멈춘 작업이 '완료'로 저장(6건) | 두 번째 `prepareRestart` 가 작업자를 끄며 바뀐 메모리 상태를 저장 | 멈춘 상태면 다시 저장하지 않음, 재시작 도구도 한 번만, 끝 상태는 `endStatus`(취소·건너뜀도 셈), 이어 하기는 done·failed 가 아닌 것을 모두 다시 |
| 멈춘 동안 일정 짜기가 끝없이 돎 | 얼린 상태에서 `runTask` 가 바로 돌아와 같은 작업을 계속 집음 | `schedule` 이 얼린 상태면 끝냄. 2분 안에 재시작이 안 일어나면 `unfreeze`(멈췄던 작업은 "중단됨") |
| 다른 PC 비추기 연결이 곧 16MB 한도에 닿을 참(첫 묶음 8.3MB) | 그 PC의 모든 작업을 통째로, 기록 한 줄까지 다 받음 | 요약(compact)으로 연결하고 이 PC 화면이 보는 세션만 자세히(`federation.setViewed`), 전체는 열 때·옮길 때 받아 옴 |
| 재시작이 기억 정리를 끊음(11건) | 유휴 판정에 정리 중이 없고 다시 하지 않음 | 정리 중이면 재시작 도구가 기다리고, 끊긴 정리는 켠 뒤 한 번 다시(`resumeCurations`) |
| 목표 판정 중 꺼지면 세션이 멈춤 | `goal.checking` 이 남음 | 불러올 때 지움 |

## 보안

- **허브 자료 폴더가 파일 보기·내려받기 범위 안**: 허브 폴더가 열기 범위라 `data/`(화면 쿠키·허브 서명 비밀, 푸시 키, 원격 설정, 브라우저 프로필)까지 읽혔다. → `opener.isPrivate`: 자료 폴더·`.env` 는 읽기·내려받기·폴더 ZIP·탐색기 열기에서 뺀다.
- **부작용이 있는 GET**: 다른 사이트의 `<img>`·fetch 로 프로세스를 띄우거나(`?force=1`) 프리미어에서 스크립트를 돌릴 수 있었다(응답은 못 읽음). → `Sec-Fetch-Site: cross-site·same-site` 인 `/api`·`/studio/api` 요청은 읽기까지 거절(화면·`/view/`·브라우저가 아닌 호출·크롬 확장은 그대로).
- **스튜디오 HTML 장면이 엔진과 같은 출처로 실행**: 장면 스크립트가 엔진 API 를 부를 수 있었다. → 장면 전용 출처(엔진 포트+1, 파일 읽기만, 등록한 폴더 안만)에서 띄우고 편집기는 postMessage 로 시각을 맞춘다. 엔진 API 도 다른 사이트 요청을 거절. `docs/studio.md`.
- 열기 범위 판정은 정션·링크의 실제 위치로, 숨은 자료 줄기(`::$DATA`)·끝의 점·장치 이름은 경로로 받지 않는다.
- **하지 않은 것**: 허브 서명에 본문 해시·1회용 번호 넣기(두 PC가 서로 다른 버전인 동안 원격 업데이트가 막힐 수 있어 따로 계획해야 한다), 화면 문서에 CSP 넣기(인라인 스크립트·스타일을 먼저 정리해야 한다).
- 문제없다고 확인된 것: DNS 리바인딩(Host 검사), 다른 출처에서 응답 읽기(CORS 머리 없음), POST 의 Origin 검사, 화면 쿠키(문서 탐색에만·HttpOnly·SameSite=Strict), 크롬 확장 통로, 원격 제어 차단, ZIP·읽기 경로, 공유 기억 경로(`safeRel`), 업로드 판별, 미리보기 프록시.

## 디스크

열흘 만에 허브 폴더 아래 약 17GB: 변경 스냅샷 8.5GB, 실행 기록 4GB(대부분 CLI 원본 기록 `events.jsonl`), 예전 작업 폴더 2.7GB, 숨은 브라우저 프로필 1GB. 지워도 줄지 않았다.
→ `lib/retention.mjs`: 하루 한 번 쉬는 때 자동 정리(주인 없는 실행 기록·7일 지난 원본 기록·30일 지난 스냅샷·브라우저 캐시·저장소 묶기), 작업·세션을 지우면 실행 기록 폴더도 지움, PC 탭 "저장 공간". 예전 작업 폴더(`workspace/`)·빌드 산출물(`desktop/dist`)·`public/` 의 결과 페이지는 사용자 것이라 건드리지 않는다.

## 속도·화면

- 스냅샷: 작업 앞뒤로 폴더 전체를 다시 읽던 것 → 안 바뀐 파일은 지난 해시를 다시 씀(큰 폴더 56초 → 1초).
- 처음 열 때: 되돌림 목록 2.5MB·1.7초 → 가벼운 목록(`/api/checkpoints?backups=1`), 화면 파일은 바뀌었을 때만 다시 받기(ETag), 원격으로 나가는 글 응답은 gzip.
- 세션 자료: 화면이 안 쓰는 것(결정 노트 사본·넣은 기억 목록·단계별 대화 id)을 뺌(22% 감소). **남은 것**: 변경 파일 목록(`checkpoint.files`, 27%)을 필요할 때만 받기 — `changes.js` 의 작업별 자료 읽기를 비동기로 바꿔야 한다.
- 화면 밖 카드는 그리기·배치를 건너뜀(`content-visibility`), 경과 시간은 그릴 때 채움, 누르는 중·선택 중인 카드는 다시 그리기를 미룸(길어도 15초), 이름 바꾸는 중·끄는 중에는 사이드바를 갈아 끼우지 않음, 영상은 화면 근처에 올 때 읽음.
- **남은 것**: 진행 중 카드를 통째로 다시 만드는 것 자체(바뀐 부분만 고치기 — 큼), 복사 버튼 코드가 문서 전체를 훑는 것(`copy.js`), 나눠 보기에서 칸마다 앱 전체가 한 벌 도는 것.

## 운영

- 스튜디오 엔진이 허브와 다른 버전으로 떠 있으면 창도 일도 없을 때 다시 켠다(`StudioLink.refreshIfStale`).
- 서버 기록(`logs/server.log`)에 시각을 붙이고 5xx·5초 넘는 요청을 남긴다. 받아 줄 곳 없는 실패(unhandledRejection)는 기록만 하고 허브를 살려 둔다.
- 시험은 동시에 8개까지만 돌린다(31개씩 돌리면 시간에 민감한 시험이 흔들렸다 — 8개로 445개 전부 통과, 걸리는 시간은 같음). 늘 실패하던 `speed.test` 정리 오류 고침.
- `AGENTS.md` 26KB → 17KB(긴 설명은 `docs/structure.md`). CLI 상태 확인은 쓰는 중에도 5분에 한 번.
